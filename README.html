OC15 - Sistema de Gestión de Órdenes de Compra

Sistema web para gestión de órdenes de compra e inventario con integración a SAP Business One.

Stack Tecnológico

ComponenteTecnología
BackendPHP 7+
Base de DatosMySQL
FrontendBootstrap 4, jQuery, AdminLTE 3
DependenciasPHPMailer, Azure Storage Blob
IntegracionesSAP Business One Service Layer, LDAP/Active Directory

Requisitos

  • PHP 7.4+
  • MySQL 5.7+
  • Composer
  • Servidor web (Apache/XAMPP)
  • Acceso a SAP Business One Service Layer

Instalación Rápida

# 1. Clonar en directorio web
git clone [repo] C:\xampp\htdocs\ordenes_compra

# 2. Instalar dependencias
composer install

# 3. Importar base de datos
mysql -u root -p ordenes_compra < ordenes_compra.sql

# 4. Configurar credenciales (ver sección Configuración)

# 5. Acceder
http://localhost/ordenes_compra/admin/

// Órdenes de Compra
$master->save_po();

// Inventario
$master->update_inventory_request();
$master->search_inventory_items();

SAPServiceLayer (Integración SAP)

$sap = new SAPServiceLayer($host, $puerto, $companyDB, $user, $pass);

// Crear solicitud de compra
$sap->createPurchaseRequest($data);

// Crear orden de compra
$sap->createPurchaseOrder($data);

// Salida de inventario
$sap->create_inventory_exit($data);

Flujo de Trabajo

1. Usuario crea OC → 2. Sistema genera PO-{random} → 3. Calcula totales/impuestos → 4. Notifica aprobadores → 5. Aprobación/Rechazo → 6. Envío a SAP Service Layer → 7. Genera documento en SAP

Super firma (gerente general): En la tabla users, el campo super_firma = 1 identifica usuarios que pueden aprobar cualquier orden de compra, sin limitarse a los departamentos asignados en aprobadores: al aprobar, el sistema actualiza todas las líneas de la OC de una vez (is_po_ready_to_be_approved en classes/Master.php). Suele asignarse al gerente general u otro perfil con facultad equivalente. El estado de super firma se puede activar o desactivar desde Actualizar Aprobadores (?page=purchase_orders/update_approver).

Campo estado_almacen (almacén / salida de mercancía)

Funcionalidades habituales de Compras

  • Solicitudes: crear OC estándar (manage_po) o modo avanzado (manage_po_compras) desde «Mis Solicitudes».
  • Actualizar aprobadores: gestionar aprobadores por departamento, activar o desactivar super firma y sustitutos en vacaciones desde purchase_orders/update_approver.
  • Revisión previa a aprobadores: en la vista de una OC (purchase_orders/view_po), el rol Compras puede usar el selector de estado Pendiente / Rechazar / Listo para aprobar (compras prepara la solicitud antes del circuito de aprobación por departamento).
  • Aprobación: si el usuario está en aprobadores para los departamentos de la línea (y no es exclusivo de inventario), puede actuar sobre solicitudes en estado «Listo para aprobar» (p. ej. tabla superior en all_purchase_orders). Quien tenga super firma puede aprobar cualquier OC como se describe arriba.
  • SAP: en vista de OC, reenvío a SAP según reglas de la pantalla (p. ej. cuando aplica mostrar número SAP y reenvío para usuarios tipo Compras).
  • Maestros y operación: agregar proveedor y artículo, gestión de usuarios listados, sincronización SAP y acceso a configuración según lo implementado en system_info.

  • Soporte para adjuntos PDF

Notas para Desarrolladores

  • Las contraseñas se hashean con password_hash() (bcrypt)
  • Archivos adjuntos se guardan en /uploads/{fecha}_OCID_{id}/
  • Los códigos SAP son obligatorios para usuarios, artículos y proveedores
  • La zona horaria está configurada en America/Bogota
  • Los logs de errores cURL se guardan en curl_error_log.json
